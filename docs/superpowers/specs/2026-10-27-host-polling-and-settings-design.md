# Our Free Model 余额 —— 第二轮设计：宿主轮询 + 设置页

日期：2026-10-27　|　第 2 轮（第一轮见 `2026-10-27-ofm-balance-chip-design.md`）
状态：**已批准**（2026-10-27，需求方确认）· **已实现**（v1.1.0）
规模：**一个项目**（宿主多出轮询器与设置存储，客户端多出一个设置页，两者都要测）

> **第 2 稿（已并入 builder check 的 7 个问题）**：修订见 §9。其中一条是第 1 稿的**事实错误**——插件源无法发现"目录外渠道"，已删。

## 1. 意图与原因

第一轮做出了「输入框旁边一个图标 + 面板」：显示当前模型所属渠道的剩余额度，点开看全部已登录渠道，用尽标红。它已经在用。

但它现在有一个说不出口的问题：**数字会过期，而界面看不出来。** 数据只在会话首次加载时取一次，之后只有按 ↻ 才更新。用户看到「491 积分」，无法判断这是刚刚的，还是半小时前的。

需求方对本轮的要求，按他自己的话：

1. 数字要**自动保持新鲜**，但**不要**自动到烦人——刷新间隔可配。
2. 要一个**独立的设置页面**（像 Our Free Model 插件那样），把显示相关的开关集中在那里；不需要的功能可以关掉。
3. **不要**算「还能用多久」（原话：「继续使用呀，不管」）——只要数字准、够新。

同时有一个现实约束：渠道余额要在宿主侧获取，而**每问一次就是 1 次发现 + N 次渠道请求**。任何「自动」方案都必须先回答「谁在什么时候问、问几次」。

## 2. 目标 / 非目标 / 反目标

**目标**

- 宿主按可配间隔轮询 OFM，缓存成一份快照；浏览器只读快照。
- 图标与面板**打开即可见**（毫秒级），不出现"先等一下 RPC"。
- 多标签页、多会话共享**同一份**快照，上游只被问一次。
- 一段时间没有任何界面在显示时，轮询自动停；有人回来立刻恢复并刷新。
- 独立设置页，可配刷新间隔与显示项；关掉的功能真的不渲染。
- 保持第一轮已确认的显示规则：只列已登录渠道、用尽标红加粗、一位小数、当前渠道用品牌色。

**非目标**

- 不做消耗速率 / 可用时长 / 「够不够」预测。
- 不做百分比或进度条（不引入分母，也就没有分母造假的风险）。
- 不做跨渠道单位换算。
- 不支持 OFM 的「桌面应用」数据源（只读 DSH 内的 OFM 插件）。
- 不做提醒/通知/推送。

**反目标（技术上能跑，但算失败）**

- 为了"自动"把上游打到限流，或让 OFM 的风控把渠道标记异常。
- 设置页与图标出现两套真相（同一件事读两个地方，改一个不生效）。
- 宿主轮询拖慢 DSH 启动，或在 OFM 缺失时刷错误日志。
- 为了"新"而编造数字：查不到就显示查不到；过期的数字必须**看得出来**是旧的。

## 3. 约束（已核实，不是假设）

1. **宿主调用 OFM 的方式**：`connection.createSharedFetchHandler('/api')` + owner Peer + 内核信封。
   - Peer 字段名跨版本：`connection.browserPeer`（DSH 0.2.1+）/ `connection.operator`（0.2.0 及更早）。本机是 0.2.1-rc.2，走 `browserPeer`；两个都读，取到哪个用哪个。
   - 信封：`{ type: 'client-request', rpcId, method: 'channel-pack', payload: { method, payload } }`，POST 到 `http://127.0.0.1/api/channel-pack`，应答被内核包一层，取 `body.result ?? body`。
   - 这是**同进程内**的合法调用；从外部 HTTP 打进来一律 401（OFM 有意锁的）。
2. **一次问出"谁登录了"**：`provider.status`，payload `{ providers: [...] }`，回 `value.statuses[provider].accounts.total`。一次往返，比逐渠道查余额再判断"空账号"省很多次。
3. **逐渠道余额**：`credits.balances`，payload `{ provider }`，单渠道一次。返回 `{ accounts: [{ accountId, nickname, balance: { total, packages }, error }] }`。
4. **单渠道慢/失败是常态**（gemini 需外网；冷启动首次约 10 秒），必须并发 + 单独超时，单个失败不能拖垮整份快照。
5. **渠道表是副本，而且无法枚举**（第 1 稿这里写错了，已改）：`provider.status` 只回显**你发过去的** id，不支持的静默丢弃，插件源**没有**任何枚举接口。所以**候选集就是内置的渠道表**；「目录外渠道自动出现」在插件源下做不到，第 1 稿的 §3.5 与对应测试用例已删。上游增删渠道时本表只能靠版本更新跟上。
6. **设置存放**：`$DSH_HOME/dsh-our-free-model-balance-zxp/settings.json`（`$DSH_HOME` = `process.env.DSH_HOME ?? ~/.dsh`），原子写（临时文件 + rename），损坏时回落到默认值而不是崩。
7. **客户端半不可单测**（页面模块加载器交付，Node 无法 import）。所以**所有能判定的逻辑必须留在宿主半**，客户端只做渲染与转发。
8. 设置页挂在 `settings.section`（列表槽，一条=一整页；宿主以 body 传送的模态呈现，回调只收到 `{ close }`）。OFM 自己占 `order: 35`，我们取 **36**，紧挨着它。

## 4. 方案（需求方已选）

| 方案 | 做法 | 代价 |
|---|---|---|
| A 客户端定时 | 浏览器按间隔自己发请求，宿主实时问 OFM | 每开一个标签页就多一份上游请求；切后台还在跑；开面板要先等一轮 RPC |
| **B 宿主轮询 + 快照**（选中） | 宿主按间隔问 OFM 并缓存，浏览器只读快照 | 宿主有后台工作；多一层缓存失效逻辑；测试更多 |
| C 宿主缓存 + 按需唤醒 | B 再加"只有客户端戳它才刷新" | 逻辑最绕；"刚打开是旧数"要额外设计 |

**选定 B，并把 C 的省电思路并进来**：宿主轮询，但一段时间没有任何界面在显示就停；有人回来立即恢复并刷新一次。

## 5. 设计

### 5.1 数据流

```
浏览器（图标/面板/设置页）
   │  GET /snapshot、POST /watch（都立即返回，本地读）
   │  POST /refresh（强制刷一次）
   ▼
宿主半 ───────────────────────────────────────────────
   │  轮询器（单飞 + 退避 + 闲置停止）
   │   ① provider.status  → 谁登录了（1 次往返）
   │   ② credits.balances → 逐渠道并发取数（每个已登录渠道 1 次）
   │   ③ 归一化 → 快照（复用第一轮的 normalizeRow）
   ▼
connection.createSharedFetchHandler('/api') + owner Peer
   ▼
OFM 的 /api/channel-pack（同进程 Fetch 路由）
```

**关键变化**：客户端不再直接调 `channel-pack`。第一轮那套「客户端取原始数 → POST 回宿主归一化」整个删掉。

### 5.2 轮询器状态机

状态：`stopped`（无人观看）/ `idle` / `polling` / `backoff`。

- **谁算"有人在看"**：客户端在挂载且页面可见时定期 `POST /watch`，页面隐藏（`visibilitychange`）即停；宿主记 `lastWatchAt`。
  - **心跳间隔 = `min(60s, autoRefreshSec)`**（`autoRefreshSec = 0` 时按 60s）。若固定 60s，用户把间隔设成 15s 后宿主每分钟会轮询 4 次，而界面 60 秒才更新一次——用户看到的是最多 60 秒前的数字，恰好与本轮目的相反。前端心跳不发上游请求，只做本地读，多标签还会被单飞合并，所以跟得上没有代价。
  - `watchTtl = 150_000ms`（2.5 分钟，容一次丢包）。
- **`/watch` 立刻返回，绝不阻塞**：返回当前快照（可能为空或旧）+ `poller.state`。
  - **何时触发轮询**：仅当 `now - lastPollAt >= max(watchTtl, 自动刷新间隔)`，即数据已经比"用户能容忍的旧"还旧时才补一次。**定时器负责间隔，心跳只负责"还有人在看"**；若心跳也按间隔刷新，每个标签页都会变成第二个调度器，用户设的间隔就没有意义了。（实现时这条取代了本节早先写的"超过 autoRefreshSec 就触发"。）
  - **等待策略**：快照里 `poller.state === 'polling'` 时，客户端每 2 秒再 `GET /snapshot` 一次，直到 state 不再是 `polling`。这是**本地读**，不产生任何上游请求——所以不违反"不要自动刷新余额"，也不会让首次挂载出现空白或等 30 秒。
  - 面板在这段时间显示「查询中…」，之前的数字保留（若已有）。
- `now - lastWatchAt > watchTtl` → `stopped`，停止一切轮询。
- 收到 `watch` 且处于 `stopped`：若已过期立即触发一次，然后转 `idle`。
- **单飞**：`polling` 期间的任何触发都合并，不排队、不产生第二次上游请求。
- **退避**：**整轮**失败（OFM 不可达 / 路由拒绝 / 无 Peer）时下一次间隔 `×2`，上限 10 分钟；任一次成功即复位。单渠道失败**不**触发退避（那是常态）。
- `autoRefreshSec = 0` 表示关闭自动刷新：轮询只由 `POST /refresh` 驱动。

### 5.3 快照形状

```json
{
  "at": 1793078507000,
  "polledAt": 1793078500000,
  "stale": false,
  "poller": { "state": "idle", "nextPollAt": 1793078560000, "error": null },
  "settings": { "autoRefreshSec": 60, "chipStyle": "number", "…": "…" },
  "channels": [
    { "id": "loomy", "name": "Loomy", "accent": "#2F6BFF",
      "unitLabel": "剩余积分", "unitShort": "积分",
      "loggedIn": true, "state": "ok", "value": 491, "amount": "491",
      "partial": false, "reason": "" }
  ],
  "loggedInCount": 3
}
```

- `state` / `value` / `amount` / `partial` / `reason` 沿用第一轮 `normalizeRow` 的语义（`value` 精确、`amount` 一位小数、`value === 0` 才是"用尽"）。
- 快照**包含未登录渠道**（`loggedIn: false`），由客户端按设置决定显不显示——这样"显示未登录渠道"开关不需要重新取数。
- **快照内嵌当前设置**：图标渲染要用到它，一次请求拿齐，不再单独 GET `/settings`（设置页仍用 `GET /settings` 拿全量与默认值）。同一标签页内设置改动立刻生效（同一个 client.js 内共享模块级 store）；**其它标签页**在下一次心跳（≤60s）拿到新设置，本轮不做跨标签实时同步。
- `channels` 顺序：内置渠道表顺序（固定 10 个）。
- `stale`：本轮失败但保留了上一轮的数据时为 `true`。

### 5.4 设置模型（schema v1）

`$DSH_HOME/dsh-our-free-model-balance-zxp/settings.json`

| 键 | 默认 | 取值 | 作用 |
|---|---|---|---|
| `version` | 1 | 1 | 迁移用 |
| `autoRefreshSec` | 60 | `0` 或 `15..3600` | 0 = 关闭自动刷新 |
| `showTimestamp` | true | bool | 面板头部的时间戳 |
| `showUnits` | true | bool | 数字后的单位（积分 / Token / USD / 配额） |
| `showSpine` | true | bool | 当前渠道的品牌色脊线与彩色数字 |
| `showFooter` | true | bool | 面板页脚汇总句 |
| `showSignedOut` | false | bool | 额外显示未登录渠道（默认藏起来） |
| `redWhenSpent` | true | bool | 用尽标红；关掉则退化为普通灰字（图标与面板同时退化，不各走一套） |
| `chipStyle` | `"number"` | `"number"` \| `"dot"` | 图标显示数字，还是只一个色点（低调模式） |
| `hiddenChannels` | `[]` | 渠道 id 数组 | **只影响面板列表**，见 §5.7 |

校验：字段类型不对 → 用默认值；数值越界 → 夹到范围内；整个文件坏 → 全部默认并把坏文件另存 `.bad`（便于反馈）。任何保存都必须原子写。

### 5.5 HTTP 接口

全部前缀 `/api/our-free-model-balance-zxp`。

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/snapshot` | 当前快照（立即返回；记一次 watch） |
| `POST` | `/watch` | 报告"还有人看着"，**立即返回快照**（可能触发一次轮询） |
| `POST` | `/refresh` | 强制轮询一次（单飞），**等待完成后**返回新快照；这是唯一会阻塞的接口 |
| `GET` | `/settings` | 当前设置 + 默认值（设置页用） |
| `PUT` | `/settings` | 校验并保存；保存后按需重配轮询器 |

第一轮的 `GET /`（渠道表）与 `POST /rows` **删除**——快照即唯一真相。

### 5.6 设置页

注册到 `settings.section`：`id: 'our-free-model-balance'`、`order: 36`、`label: '渠道余额'`。

1. **自动刷新**——下拉：关闭 / 30 秒 / 1 分钟 / 5 分钟 + 自定义秒数（15–3600）。旁注「关闭后只在点刷新时更新」。
2. **立即刷新** + 「上次更新 HH:MM」+ 轮询器状态（正常 / 查询中 / 退避中 + 原因）。
3. **显示项**——`showTimestamp` / `showUnits` / `showSpine` / `showFooter` / `redWhenSpent` / `chipStyle` 六项。
4. **渠道**——已登录渠道逐行带隐藏开关；`showSignedOut` 一个总开关（默认关）。旁注一行：「隐藏只影响面板列表；你正在用的渠道仍会显示在图标上。」
5. **恢复默认**。

改动即保存（无"保存"按钮）；保存失败在页内提示，不静默吞掉。

### 5.7 图标与面板如何消费

- 挂载时 `POST /watch`（拿快照 + 报存在）；之后按 §5.2 的心跳节奏再 `POST /watch`。
- `poller.state === 'polling'` 期间每 2 秒 `GET /snapshot`（本地读，直到不是 polling）。
- `↻` → `POST /refresh`（会等，期间显示旋转与「查询中」）。
- **`hiddenChannels` 只隐藏面板里的行**：图标永远显示当前模型所属渠道——它回答的是"我正在用的这条还剩多少"，把它藏掉等于把这个插件的唯一常驻表面删了。设置页用一句旁注说明。
- 模型切换（`modelSelection` 投影）仍只影响"当前渠道是哪一行"，不触发取数。
- 显示规则全部由设置决定；设置页与图标读**同一份**宿主持久化设置。

### 5.8 失败与降级

| 情况 | 表现 |
|---|---|
| OFM 未安装 / 路由不存在 | 轮询器 `backoff`；**保留上一轮数据**并置 `stale: true`；面板顶部一行「读不到 Our Free Model，确认它已安装并启用」 |
| 无 owner Peer（内核版本差异） | 同上，原因写「当前 DSH 未提供内核 Peer」，退避到 10 分钟，不狂重试 |
| 整轮失败但此前有数据 | **保留 last-good，不清空**：为一次抖动抹掉十个正确数字是更坏的结果。`stale: true` + 时间戳变淡 + 面板顶部原因行；数字本身不改（改了就假） |
| 从未取到过数据 | `channels: []`，面板显示原因与「重试」 |
| 单个渠道超时 / 报错 | 该渠道 `state: "unknown"` + 原因，其它渠道正常 |
| 渠道未登录 | `loggedIn: false`，默认不显示 |
| 设置文件损坏 | 用默认值；坏文件另存 `.bad` |

### 5.9 并发

- 轮询器单飞；`POST /refresh` 与定时触发同时到达时，后到者**等同一个 Promise**。
- 逐渠道并发上限 = 全部已登录渠道（最多 10 个，与 OFM 自身面板一致），不额外加信号量。
- 快照构建是纯函数：`buildSnapshot(now, discovery, rows, settings, previous)`，便于单测。

### 5.10 测试计划（全部在宿主半）

| 被测 | 用例要点 |
|---|---|
| 信封与调用 | fake `connection`（有/无 `browserPeer`、有/无 `operator`、有/无 handler）→ 断言请求体形状、`body.result ?? body` 取值、错误信息 |
| 轮询器 | 单飞（两次触发只调一次）、退避翻倍与上限、成功复位、`autoRefreshSec=0` 不自动跑、`watchTtl` 过后 `stopped`、回来立即刷新 |
| 发现 | `provider.status` 回 `{A:1,B:0,C:2}` → 只查 A、C；`provider.status` 静默丢弃未知 id 时按「未登录」处理，不报错 |
| 归一化 | 复用第一轮已测的 `normalizeRow`；「多账号取最小」「value=0 为用尽」仍成立 |
| 快照 | 顺序固定为内置表顺序、未登录也入快照、`loggedInCount` 正确、内嵌 settings |
| 陈旧保留 | 上一轮有数据 + 本轮整轮失败 → 数据保留、`stale: true`、`poller.error` 有值；从未成功过 → `channels: []` |
| 设置 | 默认值、类型错→默认、越界夹取、坏文件回退 + `.bad`、原子写（写临时再 rename） |

客户端半仍不可单测；验证靠：设置页能改能存、图标随设置变化、点刷新有反应、明暗主题下不出错、切后台 2.5 分钟后回来数字会自动变新。**这一条要在文档里写明，不许假装有测试。**

## 6. 已决定（我方裁定，需求方不必逐条确认）

1. **心跳兼取数**：`/watch` 直接返回快照，省一次往返。
2. **快照内嵌设置**：一次请求拿齐渲染所需。
3. **`/watch` 与 `/snapshot` 永不阻塞；`/refresh` 是唯一会等的接口。**"等"的观感由客户端在 polling 期间本地重读来兜（零上游代价）。
4. **快照包含未登录渠道**，由设置决定显不显示。
5. **删掉第一轮的 `/rows` 与渠道表接口**。
6. **整轮失败保留 last-good + `stale` 标记**，不清空（见 §5.8 理由）。
7. **`hiddenChannels` 只影响面板**；图标永远显示当前渠道。
8. **心跳间隔 = min(60s, autoRefreshSec)**，避免"宿主每分钟刷 4 次、界面 60 秒才更新"的自相矛盾。
9. **`redWhenSpent` 进显示项**，关掉时图标与面板一起退化为灰字（不各走一套）。
10. **渠道顺序固定为内置表顺序**，不按剩余量排序——位置稳定才形成肌肉记忆。
11. **退避上限 10 分钟**、**watchTtl 150 秒**、**polling 期间重读 2 秒**：三个经验值，实现时可微调。

- 轮询器用自调度 `setTimeout` 还是 `ctx.timer`，只要随插件卸载能停。
- 快照的 HTTP 缓存头、错误码细节。
- 是否在 `provider.status` 与 `credits.balances` 之间加 100ms 间隔（若观察到风控）。
- `settings.json` 的 `.bad` 文件命名细节。

## 8. 验收标准

1. DSH 启动后打开会话，图标**不点任何东西**就显示当前渠道余额；若首轮尚在查询，面板显示「查询中…」并在完成后自动填入（不需要手动刷新）。
2. 设置里把自动刷新改成「关闭」→ 时间戳不再自己前进，只有点 ↻ 才前进。
3. 切到后台 2.5 分钟以上再回来 → 数字**在几秒内**变新，且这期间上游没有被请求。
4. 多开两个标签页，同一时刻只发生**一轮**上游请求。
5. 设置页改任一项 → **当前标签页**的图标/面板立刻反映；另一个标签页在 ≤60 秒内跟上。
6. 把 `settings.json` 写成非法内容 → 插件仍能工作（默认值），坏文件被另存 `.bad`。
7. 禁用 OFM → 面板顶部给出可读原因；**已有的数字不消失**但标记为旧；不刷错误日志、不狂重试。
8. 隐藏某个已登录渠道 → 它从面板消失，但若它正是当前渠道，图标仍在。
9. 宿主半单测全绿；客户端半的验证按 §5.10 最后一段如实记录。
