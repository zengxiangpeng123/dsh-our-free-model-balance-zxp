# 悬浮账号卡片 —— 设计（短）

日期：2026-10-28　|　规模：**小改动**（一个组件 + 一个格式化函数）
状态：**待批准**

## 意图与原因

面板每行显示的是该渠道**所有账号之和**（2026-10-28 已按 OFM 自己的口径把「取最小」改成求和）。求和是对的——网关把请求派给池子里任意一个账号——但它把明细盖住了：你看到 Raccoon 7.3K，却不知道是两个账号各三千多，还是一个七千一个三百。

所以：**悬浮某一行时，弹出一张卡片**——上面是精确到两位小数的总额，下面是每个账号的额度。行内那个缩写数字保持不变（它负责扫一眼，卡片负责看清楚）。

## 目标

- 悬浮面板任一行 → 卡片：`总额`（两位小数 + 单位）＋ 逐账号（昵称 / 金额 / 状态）
- 输入框芯片悬浮 → 同一张卡片，内容是当前渠道
- 键盘也能得到同样信息（行可聚焦，聚焦即展开）
- 行内显示与排序完全不变

## 非目标

- 不做账号的登录 / 领取 / 编辑
- 不做历史趋势、不做跨渠道汇总
- 不改面板宽度、不改行高

## 反目标（技术上能跑也算失败）

- 卡片抢走鼠标，导致「显示→隐藏→再显示」闪烁
- 卡片被面板圆角裁掉，或越出屏幕边缘
- 卡片里出现未格式化的原始浮点（`356.2848`）
- 与行内数字打架（一处说 7.3K、卡片说 7.29K，却看不出是同一个数）

## 约束（已核实，不是假设）

1. `.ofm-balance-panel` 有 `overflow: hidden`（为裁圆角）——卡片若作为其子元素会被裁掉。必须把裁切从面板下移到列表层。
2. 面板宽 300px；卡片宽不超过面板，右对齐。
3. 宿主已提供 `row.accounts = [{ name, amount, note }]`，且 `row.value` 是**未缩写**的精确值；`amount` 是缩写串。二者都已在快照里。
4. 客户端半不可单测（页面模块加载器交付，Node 无法 import）——所以**两位小数的格式化必须留在宿主**，客户端只负责渲染。

## 方案（需求方已选 B）

| 方案 | 做法 | 结论 |
|---|---|---|
| A 原生 title 多行 | 把账号列表拼进 `title` | 零风险，但系统样式、列对不齐、约 1 秒延迟 |
| **B 自绘悬浮卡** | 行内浮出一张卡片 | **选中**：列可对齐、主题跟随、秒开、能标状态 |
| C 悬停撑开行 | 账号行直接展开在列表里 | 排除：面板高度随光标变化，列表在指针下跳动 |

## 已决定（我方裁定，可推翻）

1. **两位小数在宿主格式化**：新增 `formatExact(value)` → `7510.00` / `380.00` / `0.00`。理由见约束 4；顺带给它写单测。
2. **卡片挂在行内、右对齐、`pointer-events: none`**：卡片永不接收鼠标，因此**不可能**造成"进入→离开→再进入"的闪烁。
3. **朝上还是朝下按行号定**：列表前 60% 的行向下弹，后 40% 向上弹。不测量 DOM，纯按索引算，避免布局抖动。
4. **每行三段**：昵称（左，超长省略）· 金额（右，等宽数字）· 状态（`用尽` / `查询失败`，只在需要时出现）。
5. **行可聚焦**：`tabIndex=0`，`focus` 与 `hover` 同样展开卡片；`title` 换成 `aria-label`（完整句子），避免原生 tooltip 与卡片同时出现。
6. **芯片复用同一张卡片**，只显示当前渠道。

## 留给实现者

- 卡片的内边距与字号（沿用现有 10 / 11 / 12 三档）
- 60% 这个翻转阈值若要微调
- 超过 6 个账号时是否内部滚动（我倾向不滚动，直接变高——极少见）

## 验收

1. 悬浮 Raccoon → 卡片显示 `7510.00 积分`，下面列出 `RaccoonElizabeth (6491) 380.00` 与 `151******91 7130.00`
2. 悬浮最后一行的渠道 → 卡片朝上弹，不被面板底边裁掉
3. 鼠标从行内缓慢移到卡片方向 → 卡片不闪烁（因为不接收鼠标）
4. 行内数字仍是 `7.3K`，卡片是 `7510.00`；两者显然同源
5. 键盘 Tab 到行上也展开
6. `node --test` 全绿（新增 `formatExact` 与账号渲染数据）
