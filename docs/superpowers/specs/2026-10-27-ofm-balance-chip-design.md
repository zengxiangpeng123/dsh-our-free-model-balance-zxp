# OFM 余额小图标 —— 设计文档

> **包已更名（2026-10-27）**：包名 `dsh-ofm-balance` → `dsh-ofm-balance-zxp`，安装目录同名加后缀，接口路径 `/api/ofm-balance` → `/api/ofm-balance-zxp`。本文正文保留更名前的写法以便追溯。

> **第 3 稿 · 显示规则变更（2026-10-27，需求方确认）**：本文 §2/§9 里「列出全部十个渠道」「未登录显示为一行」的写法**已作废**，以下三条取代之：
> 1. **未登录的渠道不显示**（`state === 'empty'`，即该渠道一个账号都没有）。`查询失败`/`未返回` 的渠道**仍显示**——它已登录，只是这次没取到数；隐藏它会让渠道凭空消失。
> 2. **用尽的渠道标红**（`value === 0`）：整行红底 + 红色左边沿 + 数字位置改放一枚实心红标「用尽」（白字红底，明暗主题对比度都成立），且加粗。红是整块界面唯一饱和的颜色。
> 3. **有余额的渠道保持安静**：正常文字色、数字 15px/600 等宽；仅「当前模型所属渠道」用其厂商品牌色标记脊线与数字。
>
> 配套：一个渠道都没登录时，面板显示「没有已登录的渠道」+ 一行指路「登录 Our Free Model 的渠道后出现在这里」；页脚汇总只统计已登录渠道（`N 个可用，M 个用尽，K 个未取到`），**不提及**被隐藏的未登录渠道。当前渠道用尽时，芯片本身也显示红标。

## 1. 意图与原因

每次想知道"还剩多少额度"，都得打开 设置 → Our Free Model → 白嫖模型接入，翻到对应渠道卡片里看。选模型的时候看不到，用起来割裂。

要做的是：**把余额搬到选模型的地方**——输入框工具行最左端，紧贴模型座位。

归属：同一个人、同一台机器（已确认），不是多人共用的服务。

---

## 2. 目标（本稿修订）

- 图标常驻在输入框工具行最左、紧邻模型座位
- **点一下**：展开面板，同时发起查询；面板列出各渠道余额
- 查询完成后，图标显示**当前会话所选渠道**的余额（**仅内存，不落盘**）
- 再点一下 / 点别处：收起，已查到的数字保留在本次页面会话里
- **只对"渠道背书的模型"显示图标**；其它模型不出现

## 3. 非目标

- 不做轮询、不做定时刷新、不做后台保活
- **不点击就不发任何请求**（你已明确）
- 不改动原生模型选择器（不替换、不覆盖）
- 不做历史曲线、不做额度告警、不显示消耗速度

## 4. 反目标（做成了也算失败）

- 让 DSH 升级后碎掉
- **显示误导人的数字**（拿不到余额时假装有）
- **在用户没点的时候发请求**

## 5. 已核实的事实

> ⚠️ 本节第 1 稿曾把"网关模型前缀"误当成"渠道"，reviewer 核对代码后已更正。

| 事实 | 说明 |
|---|---|
| **渠道 = 10 张固定卡** | OFM 账号渠道页固定渲染 `lobsterai · qoder · qodercn · trae · cline · loomy · raccoon · minimax · zcode · gemini` |
| **余额接口只认这 10 个** | pack 的 `credits.balances` 按 provider 逐个调用，未知 provider 直接拒绝 |
| **`newapi` / `buddy` / `codearts` 不是渠道** | 它们在 OFM 全部文件里出现 **0 次** |
| **`our-free-model` 也不是渠道** | 它是免费车道的模型路由 id，没有余额接口 |
| **所以：模型 provider ≠ 渠道** | 只有 provider id 命中那 10 个之一时，才有余额可显示 |
| 单位不统一 | 仅 `cline`=dollars、`zcode`=tokens、`gemini`=quota，其余一律「剩余积分」 |
| 取数慢 | 单渠道可达数十秒 |
| 落点真实且是加法式 | `conversation.input.left` 已用探针实测注册成功（`active: true`） |
| 原生选择器内部无插槽 | 模型相关只有：整个座位、座位内标签（single，已被原生占用）、工具行左右两个列表位 |

## 10. 留给施工者的部分

### 已解决：当前模型的读法（原第 1 项）

**结论：不要在浏览器里找，从宿主读。**

用探针实测排除了所有客户端来源：

| 来源 | 结果 |
|---|---|
| `useInput` → `InputState` | 只有 `draft` / `attachmentIds` / `draftRev` / `phase` / `occurrences` / `queue` —— **不含模型** |
| `useConversation` | `views` / `activeTargets`，且 `activeTargets` 实测为空 |
| `useSession` | 运行状态、`openState`、`lastAgentError` 等 —— 不含模型 |
| `useProjection` | 实测返回 `undefined` |
| `useTrajectory` | 只有**请求历史**里的 `providerMetadata` / `requestConfig`，是"上次用了什么"，不是"当前选了什么" |

**正解在宿主侧，但要读对那一层。** 探针实测出两个不同的值：

```json
// 全局默认 —— 不是我们要的
agentDefaultModel.currentSelection()   →  { "provider": "newapi", "model": "agnes-2.5-flash" }

// 会话当前 —— 这才是我们要的
ctx.agents.store.get(sessionId).agent.options  →  { "provider": "loomy", "model": "DeepSeek-V4.1-Flash" }
```

**⚠️ 只看 `agentDefaultModel` 会错。** 它返回的是"新会话的默认模型"，实测为 `newapi/agnes-2.5-flash`；而 `newapi` **不在那 10 个渠道里**——照它实现，图标会在用户看得见模型的情况下错误地消失。会话级来源是 `ctx.agents.store`（`Map<sessionId, { agent: { options: { provider, model } } }>`）。

**架构后果**：插件**必须有宿主半**，由它按 sessionId 读会话级模型并通过自己的接口交给客户端——**不能做成纯客户端插件**。客户端因此完全不需要猜 hook。

**另外**：`provider` 与 OFM 渠道 id **直接同名可比**（实测 `loomy` 就是渠道表里的 `loomy`），不需要映射表。

### 仍需实现时确认（原第 2 项）

- `credits.balances` 的返回结构：每行形如 `{accountId, balance|null, error}`，需确认字段名与单位位置。
- 按 sessionId 取 agent 的**正式接口**（探针用的是 `ctx.agents.store` 这个 Map；实现时应改用服务上的公开方法，避免依赖内部字段）。
- 会话没有 agent（新会话、从未发过言）时的兜底：退回 `agentDefaultModel.currentSelection()`，或干脆不显示图标。
